¿POR QUÉ 3 ARCHIVOS EN VEZ DE 1?
════════════════════════════════════════════════════════════════════════════════

  ❌ PROBLEMA: Si agregamos columnas NOT NULL directamente:
     ALTER TABLE usuario ADD COLUMN codigo_empresa VARCHAR(50) NOT NULL;
     
     ERROR: Cannot add column - existing rows don't have values
     (Las filas existentes no tienen valor para la nueva columna)

  ✅ SOLUCIÓN: 3 fases
     1. Agregar columnas como NULL (permite filas existentes)
     2. Llenar datos usando relaciones FK existentes
     3. Convertir a NOT NULL + agregar FKs

FASE 2: LLENAR DATOS (Usar relaciones FK)
────────────────────────────────────────────────────────────────────────────────
Archivo: migrations/populate_empresa_finca_data.sql

  RELACIONES EXISTENTES:
  usuario.codigo_finca → finca.codigo
  finca.codigo_empresa → empresa.codigo

  QUERY:
  UPDATE usuario u
  JOIN finca f ON u.codigo_finca = f.codigo
  SET u.codigo_empresa = f.codigo_empresa;

  RESULTADO:
  ┌────────────────────────┐
  │ usuario                │
  ├────────────────────────┤
  │ id: 1                  │
  │ codigo_finca: FIN001   │
  │ codigo_empresa: EMP001 │ ← LLENADO automáticamente
  └────────────────────────┘

  Estado: Datos poblados usando FK existentes ✅
          NO hay registros NULL
          Listo para agregar constraints


FASE 3: AGREGAR CONSTRAINTS (NOT NULL + FK)
────────────────────────────────────────────────────────────────────────────────
Archivo: migrations/add_empresa_finca_constraints.sql

  1. Convertir a NOT NULL:
     ALTER TABLE usuario 
     MODIFY COLUMN codigo_empresa VARCHAR(50) NOT NULL;

  2. Agregar índice:
     ALTER TABLE usuario
     ADD KEY idx_usuario_empresa (codigo_empresa);

  3. Agregar FK:
     ALTER TABLE usuario
     ADD CONSTRAINT fk_usuario_empresa
     FOREIGN KEY (codigo_empresa) REFERENCES empresa (codigo);

  RESULTADO:
  ┌────────────────────────┐
  │ usuario                │
  ├────────────────────────┤
  │ codigo_empresa         │
  │ NOT NULL ✓             │
  │ FK → empresa ✓         │
  │ INDEX ✓                │
  └────────────────────────┘

  Estado: Estructura completa ✅
          Integridad garantizada ✅
          Relaciones intactas ✅

ERRORES COMUNES Y SOLUCIONES
════════════════════════════════════════════════════════════════════════════════

❌ ERROR: "Column 'codigo_empresa' cannot be null"
   CAUSA: Ejecutaste FASE 3 antes de FASE 2
   SOLUCIÓN: 
     1. DROP constraint: ALTER TABLE usuario DROP FOREIGN KEY fk_usuario_empresa;
     2. Convertir a NULL: ALTER TABLE usuario MODIFY codigo_empresa VARCHAR(50) NULL;
     3. Ejecutar FASE 2 (populate)
     4. Ejecutar FASE 3 nuevamente

❌ ERROR: "Cannot add foreign key constraint"
   CAUSA: Hay valores NULL o inválidos
   SOLUCIÓN:
     1. SELECT * FROM usuario WHERE codigo_empresa IS NULL;
     2. SELECT * FROM usuario WHERE codigo_empresa NOT IN (SELECT codigo FROM empresa);
     3. Corregir datos manualmente
     4. Intentar FASE 3 nuevamente

❌ ERROR: "Duplicate column name"
   CAUSA: Ya ejecutaste FASE 1 antes
   SOLUCIÓN: Ignorar y continuar con FASE 2

❌ VERIFICACIÓN retorna > 0 (hay NULL)
   CAUSA: Datos huérfanos o sin relación FK
   SOLUCIÓN:
     1. SELECT * FROM usuario WHERE codigo_finca NOT IN (SELECT codigo FROM finca);
     2. Corregir datos huérfanos
     3. Ejecutar FASE 2 nuevamente
